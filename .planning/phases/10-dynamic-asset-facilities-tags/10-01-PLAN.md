<objective>
Implement dynamic asset facilities and tags management for Sarpras PPKASN.

Purpose: Enable administrators to specify customized equipment, amenities, and facility tags per asset, persist them safely in PostgreSQL, manage them via an intuitive admin UI with category suggestions, and display them dynamically across public asset discovery cards, schedule modals, and booking pages with category fallback defaults.
Output: Schema update, migration script, facilities helper functions, updated server functions, enhanced admin UI, updated public UI components, and automated test suite.
</objective>

       - Add `facilities: jsonb("facilities").$type<string[]>()` to the `assets` table.
    2. Update `src/db/migrate.ts`:
       - Add idempotent migration:
         `await db.execute(sql`ALTER TABLE "assets" ADD COLUMN IF NOT EXISTS "facilities" jsonb;`);`
    3. Create `src/lib/assets/facilities.ts`:
       - Export `CATEGORY_FACILITY_PRESETS: Record<AssetType, string[]>` with Indonesian amenity presets for `room`, `dormitory`, `vehicle`, `field`, `equipment`.
       - Export `sanitizeFacilities(input: unknown): string[]` that trims, filters out non-strings or empty strings, deduplicates (case-insensitive deduplication), limits each tag to 40 characters, and caps total tags at 20.
       - Export `getAssetFacilities(asset: { type: string; facilities?: string[] | null }): string[]` that returns sanitized custom facilities if non-empty, otherwise falls back to `CATEGORY_FACILITY_PRESETS[asset.type] || CATEGORY_FACILITY_PRESETS.room`.
    4. Create `src/lib/assets/facilities.test.ts`:
       - Unit tests verifying `sanitizeFacilities` handles dirty inputs, duplicates, empty strings, and trimming.
       - Unit tests verifying `getAssetFacilities` fallback for null, empty array, and custom tags across all asset types.
    5. Update `src/db/migration.test.ts`:
       - Add test verifying that an asset created with `facilities: ["Smart TV 75\"", "Proyektor Laser"]` persists and retrieves the JSONB array correctly from database.
  </action>
  <verify>
    node --import tsx --test src/lib/assets/facilities.test.ts
