# Requirements: Milestone v1.1 - Role-Based Access Control (RBAC)

## Core Value

Users and system actions are securely segregated based on defined business roles, ensuring operators manage booking operations, admins manage users and system parameters, and leadership retains view-only monitoring.

## Requirements

### Route & Sidebar Access

- [x] **AUTH-05**: Operator cannot access User Management page (`/admin/users`) or Audit History page (`/admin/audit`).
- [x] **AUTH-06**: Pimpinan cannot access User Management page (`/admin/users`) or Audit History page (`/admin/audit`).
- [x] **AUTH-09**: System enforces route-level restrictions for non-admin roles on `/admin/users` and `/admin/audit`, redirecting them back to `/admin` if accessed directly.
- [x] **UI-NAV-01**: Sidebar navigation hides "Manajemen Pengguna" and "Riwayat Audit" links dynamically for non-admin users.

### Leadership View-Only Constraints

- [x] **AUTH-07**: Pimpinan has read-only access to assets, dashboard, and calendar (cannot create/edit/archive assets, closures, or availability).
- [x] **AUTH-08**: Pimpinan has read-only access to bookings (cannot approve, reject, or cancel).
- [x] **UI-ACT-01**: Dashboard/bookings view hides the "Setujui" and "Tolak" action buttons for Pimpinan.
- [x] **UI-ACT-02**: Booking Review Drawer hides the action footer containing approval/rejection buttons for Pimpinan.

### Backend Function Verification

- [x] **AUTH-10**: Server-side functions enforce corresponding role-based access rules:
  - [x] `getAdminsListFn` requires `admin` role.
  - [x] `getAdminAuditLogsFn` and `getAuditLogDetailFn` require `admin` role.
  - [x] `approveBookingAdminFn` and `rejectBookingAdminFn` require `operator` role (inherently allows `admin` via rank-based hierarchy).
